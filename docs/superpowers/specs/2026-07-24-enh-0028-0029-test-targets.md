## ENH-0028 — Revised Scope

**Headline correction:** The `IqamahWatchTests` target already exists and is wired in `project.pbxproj`. ENH-0028 is NOT "create a watchOS test target" — that's done. ENH-0028 is **expand coverage of the two critically untested IqamahWatch classes.**

### Gap 1: `WatchNotificationScheduler` — 0% coverage

~190 LOC handling:
- `rescheduleAll(settings:)` — 7-day prayer notification scheduling with calendar math, auth gating, per-prayer toggles
- `rescheduleFastingNow()` — Suhoor/Iftar notifications via `FastingModeEngine`
- `requestFastingReschedule()` — 0.5s debounce entry point
- `scheduleFasting(at:title:body:identifier:)` — UNNotificationRequest creation

### Gap 2: `WatchSessionManager` — 0% coverage

~51 LOC handling:
- `activate(settings:)` — WCSession delegate registration
- `session(_:didReceiveUserInfo:)` — iOS→Watch settings sync (calcMethod, asrMethod, city, timezone)

## ENH-0028 Implementation Plan

### Testability constraint — UNUserNotificationCenter

`WatchNotificationScheduler` calls `UNUserNotificationCenter.current()` directly. Mocking this requires either:
- **Protocol injection** (preferred): extract a `NotificationCenterProtocol` with `add(_:)`, `removePendingNotificationRequests(withIdentifiers:)`, `removeAllPendingNotificationRequests()`. The scheduler takes it as an init param, defaulting to `UNUserNotificationCenter.current()`.
- **Real requests** (acceptable for count/identifier tests): call `pendingNotificationRequests()` after scheduling and verify counts. Works only if test has notification auth — reliable in CI only if we skip the permission request and call the scheduling methods directly.

**Recommended:** Protocol injection. It's a small refactor to `WatchNotificationScheduler` that also benefits future maintainability.

### Testability constraint — WatchSessionManager / WCSession

`WCSession` cannot be instantiated in tests without a real Watch target. Mock via protocol:
- Extract `WatchSessionProtocol` with `activate()`, `transferUserInfo(_:)`, `isSupported()`, `isReachable`.
- Inject in `WatchSessionManager.init()`.

### New test file: `WatchNotificationSchedulerTests.swift`

```swift
@Suite("WatchNotificationScheduler")
struct WatchNotificationSchedulerTests {

    @Test("schedules 7 days of prayers for enabled prayers")
    func schedulesSevenDayWindow() async {
        let center = MockNotificationCenter()
        let scheduler = WatchNotificationScheduler(center: center)
        await scheduler.rescheduleAll(settings: .stub(city: .toronto))
        let count = await center.addedRequests.count
        #expect(count > 0 && count <= 35)
    }

    @Test("disabled prayer produces no request")
    func disabledPrayerSkipped() async {
        let center = MockNotificationCenter()
        var settings = SettingsManager.stub(city: .toronto)
        settings.disablePrayer("Asr")
        let scheduler = WatchNotificationScheduler(center: center)
        await scheduler.rescheduleAll(settings: settings)
        let asrRequests = await center.addedRequests.filter { $0.identifier.contains("Asr") }
        #expect(asrRequests.isEmpty)
    }

    @Test("reschedule removes all then re-adds")
    func removesBeforeRescheduling() async {
        let center = MockNotificationCenter()
        let scheduler = WatchNotificationScheduler(center: center)
        await scheduler.rescheduleAll(settings: .stub(city: .toronto))
        let firstRound = await center.addedRequests.count
        await scheduler.rescheduleAll(settings: .stub(city: .toronto))
        // removeAll must have been called before the second add
        #expect(await center.removeAllCallCount == 2)
        #expect(await center.addedRequests.count == firstRound)
    }
}
```

## ENH-0029 — iOS Unit Test Target

### Current state

**No unit test target exists for `iqamah-iOS`.** The `iqamahiOSUITests` target tests the UI via XCUITest. No unit-level coverage of any `iqamah/iOS/` Swift files.

### What's worth unit-testing in `iqamah/iOS/`

| File | Testable? | Key logic to cover |
|---|---|---|
| `NotificationScheduler.swift` | ✅ with protocol injection | 7-day prayer + fasting scheduling, dedup, per-prayer toggles |
| `PrayerActivityManager.swift` | ⚠️ partially | `findUpcomingPrayers()` is private; `scheduleBGRefreshTask()` wraps BGTaskScheduler — not mockable without protocol |
| `HilalWatchPreloader.swift` | ✅ | `prefetch(settings:)` pure data transformation |
| `iOSRootView.swift` | ❌ | View code — no unit-testable logic |
| `PrayerHeroCard.swift` | ❌ | View code |
| `PrayerRowMobileView.swift` | ❌ | View code |
| `HilalWatchSheet.swift` | ❌ | View code |

### Blocker: target creation requires Xcode GUI

Adding a test target to `iqamah.xcodeproj` requires editing `project.pbxproj`. The pre-commit hook blocks programmatic edits to `project.pbxproj` while Xcode is open. **The user must create the target in Xcode and commit the `.pbxproj` change manually.**

Steps to create the target in Xcode:
1. File → New → Target → Unit Testing Bundle
2. Name it `iqamahIOSTests`
3. Set "Target to be Tested" to `iqamah-iOS`
4. Add `IqamahCore` package to the test target's frameworks
5. Set minimum deployment target: iOS 17.0

### What to do programmatically (before or after target creation)

Write the test Swift files now — they can be staged in the repo and added to the new Xcode target afterward.

### Design: `NotificationSchedulerTests.swift`

`NotificationScheduler` calls `UNUserNotificationCenter.current()`. Same protocol injection pattern as watchOS:

```swift
protocol UNUserNotificationCenterProtocol {
    func requestAuthorization(options: UNAuthorizationOptions) async throws -> Bool
    func add(_ request: UNNotificationRequest) async throws
    func removePendingNotificationRequests(withIdentifiers: [String])
    func removeAllPendingNotificationRequests()
    func pendingNotificationRequests() async -> [UNNotificationRequest]
}

extension UNUserNotificationCenter: UNUserNotificationCenterProtocol {}
```

Test cases:
```swift
@Suite("NotificationScheduler (iOS)")
struct NotificationSchedulerTests {

    @Test("schedules ≤35 requests for 7 days")
    func respectsSystemLimit() async throws {
        let center = MockNotificationCenter()
        let scheduler = NotificationScheduler(center: center)
        try await scheduler.rescheduleAll(settings: .stub(city: .toronto))
        #expect(await center.addedRequests.count <= 35)
    }

    @Test("each request fires at the prayer time")
    func triggerDatesMatchPrayerTimes() async throws {
        let center = MockNotificationCenter()
        let scheduler = NotificationScheduler(center: center)
        try await scheduler.rescheduleAll(settings: .stub(city: .toronto))
        let requests = await center.addedRequests
        for request in requests {
            let trigger = try #require(request.trigger as? UNCalendarNotificationTrigger)
            let components = trigger.dateComponents
            #expect(components.hour != nil)
            #expect(components.minute != nil)
        }
    }

    @Test("disabled prayer produces no notification")
    func disabledPrayerSkipped() async throws {
        let center = MockNotificationCenter()
        var settings = SettingsManager.stub(city: .toronto)
        settings.disablePrayer("Maghrib")
        let scheduler = NotificationScheduler(center: center)
        try await scheduler.rescheduleAll(settings: settings)
        let maghribRequests = await center.addedRequests.filter {
            $0.identifier.localizedCaseInsensitiveContains("Maghrib")
        }
        #expect(maghribRequests.isEmpty)
    }
}
```

### Design: `PrayerActivityManagerTests.swift`

`PrayerActivityManager` is `@MainActor final class` with `private init()`. Can't instantiate in tests. Best approach: expose `findUpcomingPrayers` as `internal` (not `private`) so `@testable import` can reach it.

Change in `PrayerActivityManager.swift`:
```swift
// Change: private → internal (accessible with @testable import)
func findUpcomingPrayers(settings: SettingsManager)
    -> (next: (name: String, time: Date)?, following: (name: String, time: Date)?)
```

Then test via the shared singleton (safe since tests run sequentially on MainActor):

```swift
@Suite("PrayerActivityManager")
@MainActor
struct PrayerActivityManagerTests {

    @Test("finds two upcoming prayers for Toronto")
    func findsUpcomingPrayers() throws {
        let (next, following) = PrayerActivityManager.shared
            .findUpcomingPrayers(settings: .stub(city: .toronto))
        #expect(next != nil)
        #expect(following != nil)
        if let next, let following {
            #expect(following.time > next.time)
        }
    }

    @Test("returns nil-next when no city set")
    func returnsNilWithoutCity() {
        let (next, _) = PrayerActivityManager.shared
            .findUpcomingPrayers(settings: .stub(city: nil))
        #expect(next == nil)
    }

    @Test("skips Sunrise in upcoming prayers")
    func skipsSunrise() throws {
        let (next, following) = PrayerActivityManager.shared
            .findUpcomingPrayers(settings: .stub(city: .toronto))
        #expect(next?.name != "Sunrise")
        #expect(following?.name != "Sunrise")
    }
}
```

## Sequencing Recommendation

1. **ENH-0029 first** — higher value: iOS code has no unit test coverage at all. The iOS test target gap also directly affects `PrayerActivityManager` (US-0045 just landed with zero unit tests).
2. **ENH-0028 second** — the watchOS target exists; filling gaps here is additive, not remedial.
3. **Do both in one PR** — the shared `TestHelpers.swift` and `UNUserNotificationCenterProtocol` are needed by both, so shipping together avoids a messy dependency order.

The pbxproj target-creation step (manual Xcode) is the only blocking dependency. Everything else is code.

## What This Does NOT Solve

- **ActivityKit tests**: `Activity.request()` cannot run in unit tests without the Live Activity entitlement on a real device. `PrayerActivityManager.startOrUpdateActivity()` remains untested at the unit level. The BGTask submission path (`BGTaskScheduler.shared.submit`) is also not unit-testable without significant protocol extraction beyond this scope.
- **WCSession real integration**: `WatchSessionManager` tests with a mock session don't validate actual Watch↔iOS data sync. That requires physical hardware.
- **View layer tests**: None of the SwiftUI view files in `iqamah/iOS/` or `IqamahWatch/` are unit-tested. Snapshot tests in `iqamahTests` cover macOS views; iOS/watchOS views have no snapshot coverage.
