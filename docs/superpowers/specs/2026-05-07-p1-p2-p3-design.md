## 2. ENH-0001 — GPS Exact Prayer Times

**Problem:** Auto-detect maps GPS coordinates to the nearest city in `cities.json`, then uses that city's stored coordinates and timezone. A user in Brampton (43.685°N, 79.759°W) gets proxied to Toronto (43.653°N, 79.383°W), introducing a systematic offset on every prayer time.

**Solution:** Two-part fix applied only to the GPS auto-detect path. Manual city selection is unchanged.

### Option A — Immediate fix (TimeZone.current)
- Replace `TimeZone(identifier: city.timezone)` with `TimeZone.current` for GPS-detected locations.
- Use raw `CLLocation` coordinates (not the proxy city's lat/lon) for all prayer time calculations.
- ~5 lines changed in `LocationSetupView.swift` and `SettingsManager.swift`.

### Option B — Authoritative fix (CLGeocoder)
- After obtaining GPS coordinates, call `CLGeocoder().reverseGeocodeLocation(_:)`.
- From the returned `CLPlacemark`:
  - `timeZone` → authoritative timezone for the exact GPS point (overrides `TimeZone.current` for edge cases near timezone boundaries).
  - `locality` → display name shown in the app header (e.g. "Brampton", not "Toronto").
- Cache both values to `UserDefaults` alongside the GPS coordinates. Keys: `gpsLocality`, `gpsTimezone`.
- If CLGeocoder fails (offline/timeout): fall back to `TimeZone.current` + nearest city name from `cities.json`. Log the fallback.

### Behaviour rules
- Option A fires synchronously on GPS fix; Option B fires asynchronously and updates the display name when it resolves.
- Re-run CLGeocoder on each new GPS fix where coordinates differ by more than 5 km from the cached value (`CLLocation.distance(from:) > 5000`). Do not re-geocode on every app launch if cached coordinates are fresh.
- Manual city selection (via Settings sheet or onboarding) always uses the stored city coordinates and timezone — CLGeocoder is never called for manual selections.

**Files:** `LocationSetupView.swift`, `SettingsManager.swift`, `AppDelegate.swift` (status bar display name update)

## 3. BUG-0039 — Adhaan Picker Always Visible

**Problem:** The adhaan picker is hidden until hover, making US-0032 (per-prayer adhaan selection) completely undiscoverable on first use.

### Prayer row layout (revised)

```
[4px accent] [44pt icon circle] [name+NEXT VStack] [Spacer] [time right-aligned] [±controls] | [adhaan pill centred] | [mute toggle]
```

**Column breakdown:**
- **Time column** (`minWidth: 72, alignment: .trailing`): prayer time right-aligned, monospaced digits. Unchanged.
- **±controls**: immediately to the right of the time. Unchanged position.
- **Divider**: 1pt vertical line (`Color.primary.opacity(0.08)`), height 28pt, `margin: 0 12px`.
- **Adhaan column** (`width: 100pt`, centred): always-visible text pill showing current selection.
- **Mute column** (`width: 36pt`, centred): quick mute toggle button.

### Adhaan pill states
| State | Pill appearance | Mute button |
|-------|----------------|-------------|
| Sound selected, unmuted | Gold text, gold tint background, `▾` chevron | 🔔 gold tint background |
| Sound selected, muted | Struck-through text, dimmed background | 🔕 dim background |
| No sound selected | "No adhaan ▾" muted grey | `—` disabled, transparent |

- Clicking the pill opens the existing `NSMenu` / `Menu` picker. No hover required.
- Fajr pill shows Fajr-specific adhaan options; all others show standard list.
- Sunrise row: no adhaan column controls (sunrise is not a prayer).
- Mute toggle persists independently per prayer via a new `UserDefaults` key: `prayerMuteStates` (dict keyed by prayer name).
- Muting does not clear the selected adhaan — the selection is preserved and restored when unmuted.
- **Default mute state:** when a user first selects a sound for a prayer (changing from "silent"), the mute toggle defaults to unmuted (🔔). The `prayerMuteStates` dict entry is absent until explicitly toggled; absence is treated as unmuted.

**Files:** `PrayerTimesView.swift` (PrayerTimeRow, PrayerTimesTable), `SettingsManager.swift` (new mute state key)

## 4. BUG-0050 — Silent Adhaan Failure Feedback

**Problem:** When `AVAudioPlayer.play()` returns `false` (audio queue timeout, hardware unavailable), the adhaan passes silently with no user feedback.

**Fix:** In `AdhaaanPlayer.play()` and `preview()`, check the return value of `.play()`. On failure:
1. Log: `"[AdhaaanPlayer] play() returned false for \(adhaan.displayName)"`.
2. Set `@Published var audioFailed = true` on `AdhaaanPlayer`.
3. `AdhaanBannerView` observes `audioFailed`. When `true`, display a small warning line below the prayer name:

```
⚠ Audio unavailable
```

Style: SF Symbol `exclamationmark.triangle.fill` at caption size + `"Audio unavailable"` text, `Color.yellow.opacity(0.8)`. Disappears when banner dismisses. Does not block or replace the banner.

4. Reset `audioFailed = false` after the banner dismisses.

**Files:** `AdhaaanPlayer.swift`, `AdhaanBannerView.swift`

## 5. BUG-0046 — Settings Sheet Native Form Refactor

**Problem:** `SettingsSheetView` uses a hand-rolled layout (custom `SectionHeader`, manual `Divider()`, hardcoded `height: 660`). This violates macOS platform conventions, causes layout overflow on smaller windows, and is brittle to maintain.

### New structure

```swift
Form {
    Section { /* location rows */ } header: { Label("Location", systemImage: "location.fill") }
    Section { /* calculation rows */ } header: { Label("Calculation", systemImage: "function") }
    Section { /* display rows */ } header: { Label("Display", systemImage: "display") }
    Section {
        /* adjustment steppers */
        Button("Reset all adjustments", role: .destructive) { }
    } header: { Label("Adjustments", systemImage: "timer") }
}
.formStyle(.grouped)
```

### Section icons
Section headers use `Label(title, systemImage:)` matching the emoji intent from the current design:
- 📍 Location → `"location.fill"`
- 🧮 Calculation → `"function"`
- 🖥 Display → `"display"`
- ⏱ Adjustments → `"timer"`

### Display section contents
1. **Theme** — `Picker("Theme", selection: $theme)` with `.pickerStyle(.segmented)`. Options: Light / Dark / Auto. Default: Auto. Persists via `SettingsManager.colorScheme`.
2. **24-hour time** — existing `Toggle("24-hour time", isOn: $use24Hour)`.

### Sizing
- Remove hardcoded `.frame(width: 480, height: 660)`.
- Replace with `.frame(width: 480, minHeight: 480)` — height adapts to content up to the presenting window's available space.
- Minimum height governed by `Form` content, maximum by screen.

### Save / Cancel
- Retain existing Save and Cancel buttons in a bottom toolbar (`ToolbarItem(placement: .cancellationAction)` and `confirmationAction`).

**Theme application:** The `colorScheme` preference must be applied at the root. In `iqamahApp.swift`, read `SettingsManager.shared.colorScheme` and apply `.preferredColorScheme(colorScheme == "dark" ? .dark : colorScheme == "light" ? .light : nil)` on the `WindowGroup` content. This is the only place the modifier should appear.

**Files:** `SettingsSheetView.swift`, `SettingsManager.swift` (new `colorScheme` key), `iqamahApp.swift` (`.preferredColorScheme` modifier)

## 7. US-0015 — Menu Bar Left-Click Popover

**Problem:** Left-click on the status bar item currently does nothing (or shows the menu). A compact popover showing all prayer times and mute controls is the standard macOS menu bar pattern for quick-glance information.

### Interaction model
- **Left click** → `NSPopover` (this feature)
- **Right click** → `NSMenu` (redesigned, see §8)

### Popover layout (Option A — countdown-led)

```
┌────────────────────────────────┐
│ 📍 BRAMPTON · ISNA    [🔔 btn] │  ← header
│ 1:47:23                        │    countdown large (28pt bold gold)
│ until Dhuhr at 1:12 PM         │    label (11pt, muted)
├────────────────────────────────┤
│ Wednesday, 7 May · 15 Dhul...  │  ← date bar (10pt, muted)
├────────────────────────────────┤
│ Prayer          Time    Sound  │  ← column headers (9pt uppercase)
├────────────────────────────────┤
│ 🌙  Fajr      5:23 AM   🔔    │
│ ☀  Sunrise   6:48 AM   —     │  ← de-emphasised, no mute
│ 🌤  Dhuhr     1:12 PM   🔕    │  ← highlighted (next)
│ ⛅  Asr       4:47 PM   🔔    │
│ 🌅  Maghrib   8:31 PM   🔔    │
│ 🌃  Isha     10:02 PM   🔔    │
├────────────────────────────────┤
│              Open main window →│  ← footer
└────────────────────────────────┘
```

**Dimensions:** `~320pt wide`, height adaptive (fits all rows).

**Header:**
- Left: city name (11pt uppercase, muted) + countdown (28pt bold gold) + "until [Prayer] at [time]" label.
- Right: master mute button (36×36pt rounded rect, 🔔/🔕, gold tint when active, dimmed when muted) labelled "All sounds".

**Prayer rows:**
- Icon circle (28×28pt), name, time right-aligned (fixed `minWidth: 68pt`), per-prayer mute toggle (28×28pt).
- Next prayer row: gold background tint, gold text, gold icon circle tint.
- Sunrise: smaller font, no mute button, no highlighting.
- Vertical divider between time column and mute column.

**Master mute behaviour:**
- Toggles `isMasterMuted` in `SettingsManager`.
- When master-muted, all adhan playback is suppressed regardless of per-prayer mute state.
- Per-prayer mute states are preserved — master unmute restores individual states.

**Countdown timer:** fires every second (using `Timer.publish(every: 1, ...)`) while popover is visible. Pauses when popover closes.

**Footer:** plain text button "Open main window →" calls `AppDelegate.showMainWindow()`.

**Implementation:** `NSPopover` containing a SwiftUI `NSHostingView`. Attach to status bar button with `.behavior(.transient)` (auto-dismisses on click outside).

**Files:** `AppDelegate.swift` (left/right click routing, popover lifecycle), `MenuBarPopoverView.swift` (new), `SettingsManager.swift` (`isMasterMuted` key)

## 9. Design System — Preview Standard

All new UI elements must be reviewed in four variants before approval:

| Variant | Background opacity | Blur | Border |
|---------|-------------------|------|--------|
| Materials Glass · Light | `rgba(248,248,252, 0.82)` | 20px saturate(180%) | `rgba(0,0,0,0.10)` 0.5pt |
| Materials Glass · Dark | `rgba(34,34,52, 0.82)` | 20px saturate(180%) | `rgba(255,255,255,0.08)` 0.5pt |
| Liquid Glass · Light | `rgba(255,255,255, 0.38)` | 40px saturate(220%) | specular top + `rgba(120,120,180,0.25)` |
| Liquid Glass · Dark | `rgba(18,18,36, 0.42)` | 40px saturate(220%) brightness(1.12) | specular top + `rgba(160,140,255,0.20)` |

Liquid Glass specular: `::before` pseudo-element, `linear-gradient(180deg, rgba(255,255,255,0.55→0.12) 0%, transparent 100%)`, height 40–50% of element, `border-radius` matching container top.

In SwiftUI (macOS 26 target): use `.glassEffect(.regular)` inside `GlassEffectContainer`. For macOS 14/15 compatibility: use `NSVisualEffectView` with `.menu` / `.popover` material.
